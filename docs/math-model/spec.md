## 0. 目的と範囲

- 目的：数値を「部品ごとの掛け合わせ」から、**系ごとに支配するモデル**で決める形へ移す。
- 範囲：系1 戦闘の流れ／系2 資源の経済／系3 成長曲線／系4 崖と吸い込み／系5 検査／系6 測り方。
- 土台（P0）：①数値の台帳 ②計測専用モード ③流れの記録。**P0 はゲームの規則を1つも変えない。**

### 原則
1. **目標は基準プレイヤーに置く。**実際のプレイヤーの強さに合わせて敵を増やさない（投資が報われなくなる）。
2. **倍率は対数で足してから1回だけ掛ける。**合成の最大・最小が式から読めること。
3. **判断は分布で行う。**平均や1〜3周ではなく、生存曲線と信頼区間で比べる。
4. **模型は本物で検証する。**模型の予測と、本物を早回しした結果が食い違ったら模型を疑う。

## 1. 記号と単位

| 記号 | 意味 | 単位 |
|---|---|---|
| `T` | ターン（1始まり） | ターン |
| `N(T)` | そのターンの1波の人数 | 人 |
| `b` | 塊（バッチ）の大きさ | 人 |
| `g` | 塊と塊の間隔（息継ぎ） | 秒（ゲーム内時間） |
| `δ` | 塊の中の間隔（0.35） | 秒 |
| `λ` | 到着率 | 人/秒 |
| `μ` | 処理能力（関所が単位時間に倒せる人数） | 人/秒 |
| `ρ` | 負荷率 `λ/μ` | 無次元 |
| `L` | 通り道の長さ（最短経路のマス数、入口と最深部を除く） | マス |
| `K` | 通り道の上に立っている守りの数 | 体 |
| `w` | 交戦幅（同時に1人の冒険者と戦える守りの数の上限） | 体 |
| `S_r(T)` | 資源 r の残高（ターンの終わり） | 各資源の単位 |
| `I_{r,k}(T)` | 資源 r の、蛇口 k からの入り | 同上 |
| `O_{r,j}(T)` | 資源 r の、排水口 j への出 | 同上 |
| `σ` | 殻（第二形態のゲージ） | 0〜1 |

⚠ 秒は**ゲーム内時間**（`Time.deltaTime` の積算）。計測専用モードで倍速にしても変わらない量として扱う。

## 2. 系1 戦闘の流れ（待ち行列＋ランチェスター＋グラフ）

### 2.1 いまの到着の形（事実）
`DungeonAdventurerSpawner.StartWaveForThisTurn`：
- `b = clamp(ceil(N/3 × 備えの倍率), 2, 7)`
- 塊の中は `δ = 0.35` 秒おき、塊と塊の間は `g = max(5, 9 − 0.2T)` 秒
- 1波の制限時間 180 秒

したがって**到着率の平均**は
```
λ̄ = b / (g + (b−1)·δ)            （塊が続いている間）
```
例：`b=7, g=5` → `λ̄ = 7 / 7.1 ≈ 0.99 人/秒`。`N=40` なら到着に約 41 秒かかる。

### 2.2 測る量（観測）
1波ごとに、戦闘中の各時刻で「盤上にいる冒険者の数 `q(t)`」を記録し、次を出す。
```
到着数       A        = その波で湧いた人数
処理数       D        = 倒した人数 + 捕らえた人数
逃走数       E        = 帰還・逃走した人数
稼働時間     B        = q(t) > 0 だった時間の合計（秒）
処理率       μ̂       = D / B                   （稼働中の単位時間あたりの処理）
到着率       λ̂       = A / (最初の着弾から最後の着弾までの秒数 + δ)
負荷率       ρ̂       = λ̂ / μ̂
最大滞留     q_max    = max q(t)
```
⚠ `μ̂` を「稼働中の時間」で割るのは、待ち行列理論の**稼働期間（busy period）での処理率推定**に合わせるため。
　暇な時間を含めると処理能力を過小評価する。
⚠⚠ **既知の限界（v0.2）**：いまの「稼働中」は「盤上に冒険者が1人でもいる時間」で、**入口から守りまで歩いている時間を含む**。
　そのため `μ̂` は小さく、`ρ̂` は大きく出る（試運転：T1 で ρ̂ = 5.8）。P1 で「守りと交戦している時間」だけを数える形に直す。

### 2.3 関所としての迷宮（グラフ）
- 迷宮の各階の盤を**グラフ**（マス＝点、隣接＝辺）として扱い、入口→最深部の**最短経路長 `L`** を数える
  （既存 `AutoDeploy.PathToGoal`）。
- **関所**＝通り道の上で、そこを塞ぐと道が切れるマスの集合（最小カット）。関所の数 `C` を数える。
- 通り道の上の守り `K` と、その**密度** `K/L` を記録する。
- 実測（2026-09-27）：`L = 6〜9`、`K = 6〜9`、持っている配下は 1,078 体。
　⇒ **戦っているのは K 体だけ**で、持っている数は処理能力に入らない。

### 2.4 交戦幅（ランチェスター）
- 狭い通路（幅1）では、同時に戦える守りは前後の数体に限られる＝**線形則**：戦力 ∝ 質 × 数。
- 広い部屋では、囲める数が増える＝**二乗則**：戦力 ∝ 質 × 数²。
- 実装の中の定義：`w(マス)` ＝ そのマスに隣接する、守りの立てるマスの数（上限あり）。
- 処理能力の模型：
```
μ_model = Σ_{関所 c}  min(K_c, w_c) × (守り1体の実効火力) ÷ (冒険者1人の実効HP)
実効HP  = HP ÷ (1 − 軽減)               （軽減は CombatMath に一本化済み）
```
⚠ この式は**模型**。P1 で `μ̂`（実測）と並べ、ずれが大きければ式を直す。

### 2.5 人数の決め方（P2 で置き換える）
いま（9要素）：
```
N = (min(20, 3+T) + 歓喜 + 脅威の増員 + 領域の名声) × 迷宮タイプ × 難易度 × 形見 × 遺物 × 変異 + 異変 × 大招集 × 布告
```
これから：
```
N(T) = round( λ₀(T) × W × exp( clamp( Σ_i ln m_i , −Λ, +Λ ) ) ) + 異変
λ₀(T) = ρ*(T) × μ_ref(T)
```
- `ρ*(T)`：目標の負荷率の曲線（台帳 `wave.rho_target.*`）。1 を少し下回る＝**ぎりぎり捌ける**。
- `μ_ref(T)`：**基準プレイヤー**の処理能力の曲線（P1 の実測から当てはめる。台帳 `wave.mu_ref.*`）。
- `W`：到着の窓（秒）。塊の形から決まる（台帳 `wave.arrival_window`）。
- `m_i`：各要素（迷宮タイプ・難易度・形見・遺物・変異・大招集・布告・歓喜・脅威・名声）の**倍率表現**。
  足し算の要素は `m = 1 + 増員/基準人数` に直して同じ枠に入れる。
- `Λ`：合成の上限（台帳 `wave.offset_cap`）。**プレイヤーが選んで踏み越える手（大招集）だけは上限の外**に置く。
⚠ P2 の入口で、旧式と新式を同じ盤面で並べ、差がどこから来たかを要素ごとに出す（いきなり差し替えない）。

## 3. 系2 資源の経済（ストックとフロー）

### 3.1 保存則
資源 r（DP・素材・研究点・名声・威名）について毎ターン
```
S_r(T) = S_r(T−1) + Σ_k I_{r,k}(T) − Σ_j O_{r,j}(T)
```
が**帳簿の上で必ず成り立つ**こと（P0 の受け入れ条件。ずれたら記録漏れがある）。

### 3.2 蛇口と排水口の識別
- DP の入り口は 17ファイル、使い道は 28ファイル（2026-09-28 の走査）。
- ~~区分を必須の引数にする~~ → **実装では `[CallerFilePath]`／`[CallerMemberName]` で呼び出し元を自動で区分**した
  （v0.2）。呼び出し側74か所を書き換えずに**全部の出入りが漏れなく**区分つきで記録される。区分キー＝`ファイル.関数`。
- DP・素材・名声は実装済み（`ResourceLedger`）。研究点と威名は P4 で入れる。

### 3.3 物差し
```
Ī_r(T)  = 収入の指数移動平均（半減期 5 ターン）
R_r(T)  = S_r(T) / Ī_r(T)          貯まり具合（何ターン分の収入を抱えているか）
```
- 目標：`R_DP ∈ [2, 6]`（台帳 `econ.dp.reserve_band`）。
- 実測（2026-09-27）：T36 で `S_DP = 137,688`、1ターンの入り 5,000〜25,000 → `R ≈ 6〜28`。

### 3.4 排水口の形（P4）
- **規模に比例して重くなる排水口**を持つこと。固定額の排水口は後半に必ず収入に追い越される。
- 候補：維持費（配下・施設の数に比例）、深い階の掘削、儀、傭兵。

## 4. 系3 成長曲線

### 4.1 曲線の種類（台帳で名前を付ける）
| 種類 | 式 | 使いどころ |
|---|---|---|
| 線形 | `a + b·x` | 基準の伸び（1戦ごとのLvなど） |
| 対数 | `a + b·ln(1 + x/c)` | 二乗で伸びる入力（名声）を使うとき |
| 飽和 | `M·(1 − e^{−x/τ})` | 上限のある軸（段・格） |
| べき | `a·x^p` | 使うなら p を明示 |

- 伸びる量には必ず**名前と次数**を付ける。
- 両陣営の主な軸は**同じ次数**にそろえる（→ `difficulty-curve-orders`）。

### 4.2 倍率の合成
```
M = exp( clamp( Σ_i ln m_i , −Λ, +Λ ) )
```
- 掛け算を何段も重ねない。**ずれの合計に上限**を付ける。
- 合成した結果の最大・最小は `e^{±Λ}` ＝ 式から読める。

## 5. 系4 崖と吸い込み（状態遷移）

### 5.1 状態
殻 `σ` を 10% 刻みに区切り、重傷の有無と合わせて状態とする：`s = (⌊σ×10⌋, 重傷か)`。
魔王の討伐は吸収状態 `DEAD`。

### 5.2 遷移表
1波ごとに `(s_before → s_after)` を記録し、遷移確率 `P(s'|s)` を推定する（数え上げ）。
```
脱出確率    ε(s)  = P(σ_after ≥ 0.5 | s)
滞留の期待  τ(s)  = 1 / (1 − P(s|s))
```
- 受け入れ条件（P3）：`σ ≤ 0.3` の状態から、**10波以内に σ ≥ 0.5 へ戻る確率が 0 でない**こと。
- 実測（2026-09-27）：殻 22% に貼り付き、燃 4〜8 回で討たれる。⇒ 22% は実質的な吸い込み状態。

### 5.3 崖の急さ
```
崖の急さ = Δ(波あたりの魔王HPの損失) / Δρ̂
```
ρ̂ が 1 付近で急に跳ねるなら崖。**少し負ける状態**（荒廃・退がる）を入れて、なだらかにする（P3 以降）。

## 6. 系5 検査（P6）

- **最善配置の上限**：盤・配置枠・予算を固定し、`μ_model` を最大にする配置を数理計画で解く。
  最善配置でも `ρ* > 1` になるターンがあれば、数字の側の誤り。
- **支配戦略の検査**：備え×編成の損得の表を作り、どの編成に対しても最善になる備えが無いことを確かめる。
- ⚠ ゲーム中の判断（大ボタン・bot）を最適化の計算に置き換えない。**検査にだけ使う**。

## 7. 系6 測り方

### 7.1 1周の結末
| 結末 | 扱い |
|---|---|
| 魔王が討たれた（T） | **事象**（生存時間 = T） |
| 勝敗が決した（勝ち/負け） | **打ち切り**（T 時点では生きていた） |
| 上限ターン到達 | **打ち切り** |

### 7.2 生存曲線
- カプラン・マイヤー法で `Ŝ(T)` を出す。信頼区間はグリーンウッドの式（95%）。
- 報告するもの：中央値生存ターン、`Ŝ(30)`・`Ŝ(60)`・`Ŝ(100)`。
- 2つの版の比較はログランク検定。

### 7.3 試行数
- 基準は **1条件 20周以上**。差が小さい比較は 40周。
- 1周の条件：**素の状態から**（前の周の配下・DP・研究を持ち越さない。→ 既知の不具合）。

### 7.4 感度分析
- 台帳の数値を1つずつ、範囲の端まで振る（1因子ずつ／モリス法）。
- 効き目 ＝ 中央値生存ターンの変化量。効き目の順位を版ごとに出す。

## 8. 数値の台帳（JSON）

### 8.1 置き場所と読み込み
- `Assets/StreamingAssets/Balance/params.json`（ビルド後も書き換えられる場所）。
- 起動時に読み込む。エディタでは**ファイルが変わったら読み直す**。
- 読めない・値が範囲外のときは、**コードに書いた既定値**を使い、警告を出す（遊べなくはしない）。

### 8.2 1項目の形
```json
{
  "id": "wave.rho_target.base",
  "value": 0.95,
  "unit": "負荷率",
  "range": [0.6, 1.3],
  "state": "仮",
  "system": "系1",
  "why": "1を少し下回る＝ぎりぎり捌ける",
  "evidence": "",
  "updated": "2026-09-28"
}
```
| 項目 | 必須 | 意味 |
|---|---|---|
| `id` | ✓ | `系.対象.名前`。コードからはこの名前で引く |
| `value` | ✓ | 数値 |
| `unit` | ✓ | 単位（人・秒・倍・ターン・負荷率 など） |
| `range` | ✓ | 許す範囲。感度分析もこの範囲で振る |
| `state` | ✓ | `仮` ／ `測定済み` ／ `導出` |
| `system` | ✓ | どの系のモデルに属するか |
| `why` | ✓ | なぜこの値か（1行） |
| `evidence` |  | 測定済みなら、その根拠の記録（ログのファイル名など） |
| `updated` | ✓ | 最後に変えた日 |

### 8.3 コードからの使い方
```csharp
float rho = Balance.F("wave.rho_target.base", 0.95f);   // 第2引数＝既定値（台帳が無いとき）
int   cap = Balance.I("wave.batch.max", 7);
```
- **同じ id をコードの2か所で別の既定値で呼ばない**（検査で弾く）。
- 移すのは P0 では主要 50 個前後（波・経済・成長・魔王）。332 個を一度に移さない。

## 9. 計測専用モード

### 9.1 入り方
自動運転（`_AutoPlayHarness`）に `measureMode = true` を持たせる。人が遊ぶときには**絶対に入らない**。

### 9.2 変えるもの（見え方と速さだけ）
| 項目 | 通常 | 計測専用 |
|---|---|---|
| 戦闘の速さ | 1〜4倍 | **16倍**（台帳 `measure.battle_speed`） |
| 1フレームの最大時間 | 既定 | `Time.maximumDeltaTime` を抑え、移動が壁を飛び越えないようにする |
| 描画 | 通常 | カメラを止める・UIの更新を間引く |
| 音 | 鳴る | 鳴らさない |
| フレーム上限 | 既定 | 上限なし |

### 9.3 変えてはいけないもの
- ゲームの規則・乱数の使い方・判定の順番。**見え方と速さ以外は1つも変えない。**

### 9.4 等価性の検証（P0 の受け入れ条件）
- ~~1倍×10周と比べる~~ → 1倍は1周50分で10周に8時間を超えるため、**プレイヤーが実際に使う4倍速を対照**にした（v0.2）：
  「4倍×10周」と「16倍×10周」を回し、**生存曲線にログランク検定で差が出ない**こと（p > 0.05）、
  かつ **ターン帯ごとの撃破率・逃走率・魔王HPの損失**が大きく食い違わないこと（`tools/analyze/survival.py`）。
- 食い違ったら、速さを下げる（16 → 8 倍）。
- **結果（2026-09-28・`docs/measure/report_equivalence.md`）**：4倍×10周 中央値 T25（95% T18〜26）／16倍×10周 中央値 T26（T23〜27）、
  ログランク p = 0.070 ＝**基準は満たした**。ただし境界に近く、16倍がわずかに守り有利（T16〜20 の魔王HP損失 0.12 対 0.07）。
  ⇒ **ふるい分けは16倍、最終判断は4倍で確かめ直す**運用にする。
- ⚠ 検証の途中で**計測を汚す不具合が2つ**見つかり、2回やり直した：
  ① 撃破の二重計上（同じフレームの2回目のダメージで撃破処理が再度走る。速いほど起きる）→ ゲーム本体を修正
  ② 自動運転が戦闘中の手を**実時間**0.35秒ごとに打っていた（速さで手の頻度が変わる）→ ゲーム内時間に修正

### 9.5 周の独立
各周の開始時に、配下・DP・研究・遺物などを**素の状態に戻す**。
- 実装（v0.2）：① `Reset()` を持つのに呼ばれていなかった9つのうち8つを `StartNewGame` で呼ぶ
  （配下・眷属・天啓・遠征・奔流・出来事・敵の経営。`SurfaceMap` は `Regenerate` が担う）。
  ② 場面の部品（魔王・遺物・感情ツリー）は `RunBaseline` が**最初の開始の直前の中身を写し、以後そこへ戻す**。
- 検査：自動運転が周の頭に**指紋**（魔王Lv・BP・遺物・感情・配下・眷属・天啓・研究・DP・素材・名声・敵の名声とDP）を
  記録する。どの周も同じ値で始まること（試運転3周で一致を確認）。

## 11. P0 の作業と受け入れ条件

| # | 作業 | 受け入れ条件 |
|---|---|---|
| 1 | `Balance`（台帳の読み込み・既定値・範囲検査・読み直し） | 台帳を消しても遊べる。範囲外の値で警告が出る |
| 2 | 台帳へ主要 50 個前後を移す（まず系1・系4 の分） | 移す前後で自動運転の結果の分布が変わらない |
| 3 | `AddDP/TrySpendDP` に区分を必須化、素材・名声も | 保存則 §3.1 が全ターンで成り立つ |
| 4 | 流れの記録 CSV（§10） | 1周ぶんが欠けなく出る |
| 5 | 計測専用モード（§9）＋周の独立（§9.5） | 1周 5分以下／等価性の検証 §9.4 を通る |

⚠ P0 のあいだはゲームの規則を変えない。数値を台帳へ移すときも**値は今のまま**。
